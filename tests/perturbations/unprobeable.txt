# The cases that ask for the reachability probe and cannot have one, as of 2026-09-14.
#
# The probe is inserted as a statement ahead of the line the anchor begins on. Two anchor shapes have
# no line that can take one: a continuation line inside a multi-line expression, which is what an
# anchor quoting one dict entry or one f-string fragment lands on, and an `elif` or `except` clause
# header, which cannot have a statement above it. Those cases still run, and the sweep prints
# `note ... reachability is unestablished` for each, but nothing establishes that the line they
# perturb executes. Red for them could be red about anything.
#
# Declared here rather than in a comment beside each case so it is checked.
# `tests/test_perturbation_harness.py::test_the_cases_that_cannot_take_a_probe_are_declared_here`
# reads this file and requires the set to match exactly, so a new case cannot join the list quietly
# and a case that becomes probeable cannot stay on it.
#
# If that test sends you here, you have three options and only the third is free: re-anchor the case
# on the whole statement rather than a fragment inside it, pass `probe=False` and say in the script
# why reachability cannot be established for it, or add the line the test prints. 23 lines today, 18
# continuation lines and 5 clause headers, and a smaller number is the direction.
#
