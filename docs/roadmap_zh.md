## 日志查询与分区

| | |
|---|---|
| 对小时级分区的日志也能做明细分析（并在开始前提示扫描成本更高），而不是直接拒绝 | 2026-09-10 |
| 桶内前缀格式中途变过的情况下，正确识别分钟级分区 | 2026-09-09 |
| 桶里同时存在两种分区格式时，告诉你从哪一天起可以做分钟级日志查询 | 2026-09-09 |
| 支持分区列不叫 `log_time` 的现有 Athena 表，前提是分钟级分区。小时级的表能被认出来，但明细查询仍然会被拒绝 | 2026-09-09 |
| 不再漏掉查询窗口边缘的记录。日志里的时间戳，和它实际落在哪个分区目录，两者并不总是对得上 | 2026-09-09 |
| 自动识别 Firehose S3 日志路径使用的非 UTC 时区，避免查询静默漏掉数据 | |
| 查询结果时间在所有数据源上统一按你的会话时区显示 | 2026-09-09 |
| 读取你自己转换好的 Parquet 格式 WAF 日志表 | |

关于接受小时级分区的取舍和背后的实测数据，见[小时级 vs 分钟级分区](hourly-vs-minute-partitioning_zh.md)。
