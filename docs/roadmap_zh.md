# 路线图

[English](roadmap.md) | 中文

从现在起我们计划支持什么、修复什么。已经做完的在 [CHANGELOG](../CHANGELOG.md) 里，不在这里。

下面所有条目都没有日期，因为都还没做，也不构成承诺。某项发布后，日期会写在右侧。每组里大致按我们打算动手的顺序排列，顺序可能会变。

## 日志查询与分区

| | |
|---|---|
| 对小时级分区的日志也能做明细分析（并在开始前提示扫描成本更高），而不是直接拒绝 | |
| 桶内前缀格式中途变过的情况下，正确识别分钟级分区 | |
| 桶里同时存在两种分区格式时，告诉你从哪一天起可以做分钟级日志查询 | |
| 支持分区列不叫 `log_time` 的现有 Athena 表 | |
| 读取你自己转换好的 Parquet 格式 WAF 日志表 | |

关于接受小时级分区的取舍和背后的实测数据，见[小时级 vs 分钟级分区](hourly-vs-minute-partitioning_zh.md)。

## 长时间查询

| | |
|---|---|
| 大查询运行期间保持连接，并显示扫描进度 | |
| 问题所需的扫描范围超出单轮能力时，直说，并给出该换成什么问法 | |
| 在代码里强制查询时间窗口上限，而不只是靠提示约束 | |
| 最耗时的绕过检测扫描下钻改成候选列表由你挑选，而不是自动跑完整条链 | |
| 停止按钮真正取消 Athena 查询，而不只是断开浏览器请求 | |
| 报告里某段被跳过时明确说出来，而不是留一片空白 | |

## 分析能力

| | |
|---|---|
| 一个通用的日志聚合查询，任意受支持的过滤条件搭配任意受支持的分组维度 | |
| 规则级和端点级命中率，包括 Count 切 Block 之后的误报率 | |
| 引导式 SQL 注入调查，和现有的误报调查、绕过调查一样成体系 | |
| 识别同一个 WAF token 在大量 IP 上被复用 | |
| 国家、referer、网络（ASN）集中度作为补充维度 | |
| 用域名找到对应的 WebACL，不再反问你是哪一个 | |
| 巡检报告里跨 WebACL 的汇总 | |
